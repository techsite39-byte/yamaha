## Blockers

1. **[goal_coverage] Local native authentication must remain usable without restoring built-in credentials.**
   - **Required property:** A fresh/empty local auth store has a safe, documented way to provision its first administrator while retaining the promised local native login and not seeding built-in credentials.
   - **Evidence:** Task 1 changes a missing store to an empty store and removes `DEFAULT_ADMIN`; no initial-account provisioning path is planned. Task 3 nevertheless claims native local login remains. In an empty store, `verifyAdminCredentials` cannot authenticate anyone, and admin-user creation is behind protected admin access.
   - **Example fix (non-binding):** Define and verify an explicit operator-controlled bootstrap/provisioning path consistent with the no-default-credentials decision.

2. **[reset_safety] Reset behavior must remain safe and usable when SMTP is not configured.**
   - **Required property:** If reset-code delivery is unavailable, no code is exposed or left usable in storage, and the outcome is handled/tested without breaking the supported reset flow.
   - **Evidence:** Task 2 covers a rejected mail send, but not `isSmtpConfigured() === false`. The live route currently has a separate no-SMTP branch that returns the code, and `YamahaAdminLogin.jsx` consumes `res.code`; Task 2 removes code disclosure but does not plan a frontend change or define the unconfigured-transport outcome. Thus the current no-SMTP path cannot be shown to remain safe and functional.
   - **Example fix (non-binding):** Specify and test the no-transport outcome, including pending-code cleanup and the user-facing flow, without returning the code.

## Warnings

1. **[nyquist_compliance] Automated checks lack explicit failing-direction declarations.**
   - **Required property:** Each runnable `<automated>` command states what failure output/exit condition makes its task fail.
   - **Evidence:** The four commands across Tasks 1–3 have no `<fails_when>` siblings.
   - **Example fix (non-binding):** Add a failing-direction declaration for each command.

2. **[reset_safety] The rate-limit acceptance boundary is not measurable from the plan.**
   - **Required property:** Tests establish the enforced request/verification limit and the boundary at which further attempts are rejected.
   - **Evidence:** Task 2 says “bounded rate limits” and “rate limiting” but gives no limit/window/scope or explicit boundary assertion.
   - **Example fix (non-binding):** Define a measurable bound and have the isolated tests assert the allowed and rejected cases.
